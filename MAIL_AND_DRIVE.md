# Почта и облачный диск комплекса

Комплекс регистрирует свои аккаунты сам — значит, у него есть свои ящики и свой
диск. Здесь описано, что это за ящики, где лежат их пароли и как ими
пользоваться изнутри цикла и из облака.

**Правило, которое важнее остальных:** репозиторий `vasiliad/kg` — ПУБЛИЧНЫЙ.
Настоящий пароль от ящика не имеет права попасть в него ни разу — ни в `.env`,
ни в README, ни в коммит, ни в лог цикла.

## 1. Инвентарь

| Провайдер | Адрес | Что это | Чем читается |
|-----------|-------|---------|--------------|
| **Proton** | `vanvasiliadi@protonmail.com` | Основной ящик. На нём же поднят **облачный диск Proton Drive** (2 ГБ на Free). | Вручную (веб) / через Proton API |
| **Tuta** | `ivan.vasiliadi@tutamail.com` | Запасной ящик у другого провайдера. Recovery-код — единственный путь обратно. | Вручную (веб) |
| **mail.tm** | `xray1793739979@fldubai.com` | Единственный ящик с **открытым REST API** — поэтому единственный, который комплекс читает без человека. | `harness/mail_accounts.py` |
| **Proton Drive** | Shares the Proton login | Облачный диск: 2 ГБ, шифрование на стороне Proton. Третья копия записи комплекса — её держит сам комплекс. | `harness/proton_drive.py` → `rclone` (remote `protondrive:`) |

Три провайдера — потому что один мёртвый провайдер не должен заглушить
комплекс. Если Proton ляжет, код подтверждения придёт в Tuta; если и Tuta
ляжет — в mail.tm.

## 2. Где живут пароли

| Где | Что | Когда нужно |
|-----|-----|-------------|
| `.env` в корне репозитория | Все значения открытым текстом. Файл в `.gitignore`, никогда не коммитится. | Локальные запуски на своей машине |
| **Запечатанный vault** `data/.sealed_vault.json` | Только шифротекст: AES-256-GCM под солью `VAULT_SALT` / `REDACTION_SALT`. | Облако и любой хост, у которого есть соль |
| GitHub Actions secrets | Те же имена, что и в `.env` | Рабочие процессы GitHub Actions |
| `RCLONE_CONFIG_PROTONDRIVE_*` | Переменные окружения, которые сам комплекс собирает из vault/secrets. Конфиг-файла rclone у комплекса нет. | Копирование на диск (шаг workflow или локальный запуск) |

Ключи в vault:

```
proton:address  proton:username  proton:password  proton:plan
tuta:address    tuta:password    tuta:recovery_code
mailtm:address  mailtm:password  mailtm:token
drive:address   drive:password   drive:tfa
```

## 3. Чтение почты

```bash
python -m harness.mail_accounts --list                    # красный инвентарь (без паролей)
python -m harness.mail_accounts --inbox                   # последние письма mail.tm
python -m harness.mail_accounts --inbox --grep github     # только про GitHub
python -m harness.mail_accounts --inbox --wait 60         # опрос до 60 секунд
```

Код подтверждения (6–8 цифр) вытаскивается из письма автоматически и печатается
строкой `codes:`. Модуль никогда не печатает пароль: в выводе — только маска
(`Xr***********!`) и sha256-отпечаток адреса.

Токен mail.tm может протухнуть. Модуль это понимает: если сохранённый токен
не проходит, он логинится заново по адресу и паролю. Держите пароль под рукой —
восстановление mailbox недоступно без него.

### Живой путь (что уже проверено)

```bash
python -m harness.mail_accounts --inbox
# [2026-11-04T13:06:12Z] noreply@github.com :: Your GitHub launch code
#     codes: 08502479
```

## 4. Запечатывание

Скрипт `scripts/seal_mail_accounts.py` кладёт значения в vault. Перед записью он
**доказывает**, что соль верна: открывает уже существующую запись
(`mega:email` / `mega:password` / `mega:mailtm_token`). Неверная соль роняет
проверку GCM-тега — не «мусор», а отказ, — и скрипт отказывается писать то,
что облако потом не прочитает.

```bash
python scripts/seal_mail_accounts.py --check   # только проверить соль
python scripts/seal_mail_accounts.py           # запечатать (идемпотентно)
python scripts/seal_mail_accounts.py --force   # запечатать, даже если vault не открылся
```

Идемпотентность важна: неизменное значение не перешифровывается, иначе файл
vault дрожал бы при каждом запуске и засорял историю репозитория.

В облаке то же самое делает workflow `.github/workflows/seal_mail_accounts.yml`
(запуск вручную, `workflow_dispatch`): он получает соль и все mailbox-переменные
из secrets, запечатывает и коммитит `data/.sealed_vault.json` обратно.

> **Перед первым запечатыванием** заполните `PROTON_DRIVE_2FA_SECRET` (TOTP-секрет
> Proton) и добавьте его в GitHub secrets. Если на аккаунте включена двухфакторная
> аутентификация, облако без TOTP-секрета не войдёт в Drive.

## 5. Облачный диск (Proton Drive)

Диск держит **сам комплекс** — своим раннером (GitHub Actions) или локально.
Доступа к чужим VPS у комплекса нет: remote `protondrive:` собирается из
учётных данных, которые лежат в vault/secrets.

Рабочая схема — **не mount**, а `rclone copy` отдельным шагом workflow: mount
эфемерный и умирает вместе с runner'ом, а копия — нет. Модуль
`harness/proton_drive.py` делает весь цикл сам:

```bash
python harness/proton_drive.py        # копия + проверка чтением обратно
```

Что он делает, по порядку:

1. Берёт адрес/пароль/TOTP из окружения (`PROTON_DRIVE_ADDRESS`,
   `PROTON_DRIVE_PASSWORD`, `PROTON_DRIVE_2FA_SECRET`), а если их там нет —
   из запечатанного vault (`drive:address`, `drive:password`, `drive:tfa`).
2. **Обфусцирует пароль сам** — тем же AES-CTR, что и rclone. Отдавать rclone
   открытый текст бесполезно: он ответит `couldn't decrypt password ... is it
   obscured?`. Вызывать `rclone obscure` тоже нельзя — тот принимает пароль
   аргументом командной строки, то есть секрет попадёт в список процессов.
3. Собирает remote в **переменных окружения** — `RCLONE_CONFIG_PROTONDRIVE_TYPE`,
   `_USERNAME`, `_PASSWORD`. Конфиг-файла rclone у комплекса нет, пароль не
   попадает ни в аргументы, ни в лог.
4. Копирует известные файлы состояния в `protondrive:/immortal/` через
   `rclone copy`.
5. **Читает каждый файл обратно** (`rclone cat`) и сверяет байты с оригиналом.
   Это и есть доказательство: не «rclone не ошибся», а «то, что лежит на
   диске, совпадает с тем, что было здесь».

Итог пишется в `data/proton_drive_report.json`:

| Поле | Что значит |
|------|-----------|
| `status` | `ok` — всё залито и сверено; `partial` — что-то не залилось или разошлось; `failed` — копии нет |
| `count` / `verified` | Сколько файлов залито / сколько прочиталось байт-в-байт |
| `account` | Отпечаток адреса, не сам адрес |
| `source` | `environment` или `vault` — откуда взялись учётные данные |
| `two_factor` | `on` / `off` — включена ли двухфакторная аутентификация на аккаунте |
| `missing` | Каких файлов состояния нет на этой машине (их не копировали) |
| `notes` | Замечания, не сломавшие обещание (например, файл состояния отсутствует) |
| `degraded` | Есть ли замечания: копия на месте, но что-то сказать надо |

Красный `partial` — это ненулевой код выхода: workflow падает, если копия не
полная. Зелёный `ok` означает ровно одно — «обещание выполнено».

### Кто зовёт этот модуль

- **Облако:** `.github/workflows/proton_drive_sync.yml` — cron `40 5 * * *`
  (после дневного дайджеста и после MEGA-архива), плюс ручной запуск.
  Workflow ставит rclone сам: раннер его не несёт, поэтому ставится **версия,
  которую пиннит этот коммит**, и сверяется официальной sha256 до установки.
- **Цикл-супервизор:** `harness/cycle_supervisor.py` знает цикл
  `proton_drive`, артефакт — `data/proton_drive_report.json`. Если артефакт
  протух, супервизор перезапускает workflow. Супервизор смотрит на **возраст
  артефакта**, а не на вывод прошлого запуска: красный прогон не должен
  превращаться в цикл перезапусков.
- **Здоровье комплекса:** `harness/daily_dispatcher.py` читает тот же отчёт и
  показывает в письме оператору отдельный блок «Proton Drive — копия на
  диске» с папкой, числом файлов, отпечатком аккаунта и временем проверки.
  Правила те же, что у MEGA-архива: копия сверена — «копия на месте»; есть
  замечания — «копия на месте, но есть замечания»; отчёта нет — «состояние
  неизвестно» (и никогда «копия на месте»).

### Три ошибки, на которых уходит время

1. **`app_version` задавать не надо.** В rclone ≥1.74 опция есть, но rclone
   сам выводит корректное значение из своей версии. Руками заданная строка
   `external-drive-rclone@v1.74.3` отбивается Proton'ом: `Code=2064 Invalid
   version number`, а `external-drive-rclone@1.74.3` — `500 Internal server
   error`. Оставьте `app_version` пустым.
2. **Корневой шэр создаётся только веб-клиентом.** Если Drive ни разу не
   открывали в браузере, список `shares` пуст и rclone падает с
   `the main share assumption has failed` — при полностью верном логине и
   пароле. Лечится один раз: зайти на `https://account.proton.me/drive` под
   учёткой Proton и открыть «My files». **Для этого аккаунта уже сделано**,
   корневой шэр существует и проверен сквозной записью.
3. **Прокси — в окружении, а не в флаге.** В rclone 1.74.3 флага
   `--proxy-server` **больше нет** (заметка оператора его ещё упоминала) —
   rclone говорит `unknown flag`. Правильный путь — стандартные переменные
   `HTTPS_PROXY` / `HTTP_PROXY`, которые комплекс ставит сам, если задан
   `PROTON_DRIVE_PROXY`.

> Из российских сетей `proton.me` не открывается напрямую (соединение
> сбрасывается через ~35 с, тогда как `api.mail.tm` отвечает за 0.48 с).
> Локальные запуски ходят через собственный xray:
> `PROTON_DRIVE_PROXY=http://127.0.0.1:10809 python harness/proton_drive.py`.
> Раннер GitHub находится вне этой сети и ходит напрямую.

## 6. Что нужно помнить

- **Tuta Free удаляет аккаунт**, если в него не заходить 6 месяцев. Нужен
  периодический keep-alive — иначе recovery-код останется, а ящика уже нет.
- **Proton и Tuta читаются только человеком.** Для автоматических кодов
  подтверждения используется mail.tm.
- **Пароль ящика = пароль входа в Proton Drive** (если 2FA выключена). Это
  один и тот же секрет в двух местах — поменяли в Proton, поменяйте и в `.env`,
  и перезапечатайте vault.
- **`.env` не коммитится.** Если он всё же попал в историю — пароли считаются
  скомпрометированными, а не «спрятанными».

## 7. Куда идти дальше

- Telegram-бот комплекса может слать коды подтверждения в рабочий ящик —
  маршрут «mail.tm → бот» уже работает.
- **Синхронизация `data/` комплекса на Proton Drive — сделано.** Цикл
  `proton_drive` копирует состояние на диск и читает обратно; артефакт
  `data/proton_drive_report.json` показывает состояние копии, а супервизор
  поднимает её, если копия протухла. Три копии записи теперь: репозиторий,
  MEGA-архив, Proton Drive.
- **Осталось от человека:** соль `VAULT_SALT` в локальном `.env` (в Actions
  она есть, а локальный vault без неё не открыть), второй Gmail-отправитель
  (`GMAIL_SENDER_2` / `GMAIL_APP_PASSWORD_2`) и адрес для архивной копии
  (`ARCHIVE_RECIPIENT_EMAIL`) — комплекса в этом смысле два Google-аккаунта
  пока не заменить.
- Резервная копия самого vault: файл шифротекста можно хранить где угодно —
  открыть его можно только солью.
